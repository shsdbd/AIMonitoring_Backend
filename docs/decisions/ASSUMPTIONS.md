# 02_ASSUMPTIONS (가정 사항)

이 문서는 프로젝트 진행을 위해 현재 '사실'로 간주하여 설계 및 구현에 반영하고 있으나, 추후 시스템 환경이나 요구사항 구체화 단계에서 **반드시 검증 및 확정이 필요한 임시 전제 조건**들을 기록합니다. 
가정이 거짓으로 판명될 경우 시스템 아키텍처나 코드가 수정될 수 있습니다.

## 1. AI 모듈(드론/CCTV) 연동 환경
- **통신 프로토콜:** AI 모듈은 백엔드 서버와 실시간 HTTP 통신이 가능하며, 장애물 탐지 즉시 REST API (POST)를 통해 데이터를 전송한다고 가정한다. (별도의 MQTT나 Kafka 같은 메시지 큐 시스템은 초기 MVP에 없다고 전제함)
- **네트워크 안정성:** 드론 및 외부 CCTV는 이미지(파일)와 위치 데이터를 즉각 전송할 수 있는 안정적인 무선 인터넷(LTE/5G 등) 환경에 연결되어 있다고 가정한다. 단절 상황에 대한 재전송 처리는 AI 모듈 기기 단에서 수행한다고 전제한다.
- **좌표계 표준:** 장비가 보내는 위도(`latitude`)와 경도(`longitude`) 데이터는 일반적인 지도 API(카카오맵, 구글맵 등)와 즉각 호환되는 WGS84 표준 좌표계를 따른다고 가정한다.

## 2. 데이터 발생량 및 인프라 부하 (MVP 기준)
- **트래픽 규모:** 초기 MVP(최소 기능 제품) 환경에서는 동시 다발적인 장애물 탐지 이벤트가 초당 50건을 초과하지 않는다고 가정한다. 따라서 현재의 단일 FastAPI 인스턴스와 단일 PostgreSQL 컨테이너만으로 부하 처리가 가능하다고 전제한다.
- **스토리지 용량:** 업로드되는 장애물 이미지는 건당 2~5MB 이하로 최적화되어 전송되며, 현재 설정된 서버 내부 볼륨(`/static/images/`)에 저장해도 단기간 내에 용량이 고갈되지 않는다고 가정한다. (추후 실제 데이터가 쌓이는 속도를 보고 외부 클라우드 스토리지 도입 여부를 논의함)
