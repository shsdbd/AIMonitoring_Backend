# 03_OPEN_QUESTIONS (미결정 질문 사항)

이 문서는 프로젝트 설계 및 구현 과정에서 도출되었으나 아직 확정되지 않은 기술적/기획적 질문들을 기록합니다. 다음 단계(특히 User, Equipment 연동 및 프론트엔드 통신 단계) 진입 전이나 구현 중에 반드시 합의를 거쳐 `DECISIONS.md`로 이동시켜야 합니다.

## 1. 인증 및 인가 (Authentication & Authorization)
- **Q1. 관제사(User) 로그인 방식:** 프론트엔드 대시보드 접속 시 JWT 기반의 자체 로그인을 구현할 것인가, 아니면 OAuth(구글, 카카오 등)를 연동할 것인가?
- **Q2. AI 모듈(Equipment) API 인증:** 드론이나 CCTV가 `POST /api/v1/events` 엔드포인트를 호출할 때, 무단 접근을 막기 위해 어떤 인증 방식(예: API Key, JWT 토큰, IP 화이트리스트)을 적용할 것인가?

## 2. 실시간 통신 및 알림 (Real-time Communication)
- **Q3. 대시보드 실시간 업데이트:** 새로운 장애물(Event)이 DB에 인서트 되었을 때, 프론트엔드 대시보드가 이를 즉시 알 수 있도록 WebSockets이나 SSE(Server-Sent Events)를 구현해야 하는가? (현재는 단순 폴링/GET 요청으로 가정 중)

## 3. 데이터 보존 정책 (Data Retention)
- **Q4. 이미지 및 데이터 만료:** 서버 볼륨에 저장되는 장애물 이미지와 DB 레코드는 영구 보존할 것인가, 아니면 일정 기간(예: 30일)이 지나면 자동 삭제(Batch/Cron Job) 처리할 것인가?

## 4. AI-Backend-Frontend 데이터 연계
- **Q5. AI -> 백엔드 요청 형식:** AI 모듈이 백엔드로 전송할 공식 데이터 형식은 `multipart/form-data`로 이미지 파일을 직접 포함할 것인가, 아니면 JSON으로 이미지/영상 참조 URL만 전달할 것인가?
- **Q6. AI 탐지 bbox 좌표 기준:** `bbox_x`, `bbox_y`, `bbox_width`, `bbox_height`는 원본 이미지 픽셀 기준으로 전달할 것인가, 아니면 `0~1` 정규화 좌표 기준으로 전달할 것인가?
- **Q7. bbox 기준점:** `bbox_x`, `bbox_y`는 장애물 박스의 좌상단 좌표를 의미할 것인가, 중심점 좌표를 의미할 것인가?
- **Q8. 프론트엔드 표시 매핑:** AI가 전달한 bbox 좌표를 프론트엔드의 실시간 영상/이미지 화면 크기에 어떻게 매핑할 것인가?
- **Q9. priority 값 체계:** `priority`는 숫자형 등급으로 관리할 것인가, 문자열 enum(`LOW`, `MEDIUM`, `HIGH` 등)으로 관리할 것인가?
- **Q10. 실시간 영상 연계 방식:** 관제 화면의 실시간 영상은 백엔드가 `video_url`/`stream_url`을 관리해야 하는가, 아니면 프론트엔드가 별도 영상 소스를 직접 연결할 것인가?
- **Q11. 처리 기록 기능의 MVP 포함 여부:** 관제사의 코멘트/처리 기록 작성 및 조회를 이번 MVP에 포함할 것인가, 아니면 상태 변경만 우선 구현하고 후순위로 둘 것인가?
- **Q12. 이벤트 목록/상세 표시 필드:** 프론트엔드 목록과 상세 화면에서 반드시 표시할 이벤트 요약/상세 정보는 어디까지로 정할 것인가?
- **Q13. 정보 부족 이벤트 처리 방식:** AI 탐지 결과에 필수 정보가 부족한 경우 이벤트 등록을 거부할 것인가, 별도 상태로 저장해 관제사가 인지하게 할 것인가?
- **Q14. AI 파트 미완성 시 통합 검증 방식:** AI 파트가 MVP 통합 시점까지 준비되지 않은 경우, 테스트 클라이언트나 샘플 요청 데이터로 AI 탐지 이벤트를 대체해 검증할 것인가?
