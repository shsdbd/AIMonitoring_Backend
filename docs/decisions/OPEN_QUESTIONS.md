# 03_OPEN_QUESTIONS (미결정 질문 사항)

이 문서는 프로젝트 설계 및 구현 과정에서 도출되었으나 아직 확정되지 않은 기술적/기획적 질문들을 기록합니다. 다음 단계(특히 User, Equipment 연동 및 프론트엔드 통신 단계) 진입 전이나 구현 중에 반드시 합의를 거쳐 `DECISIONS.md`로 이동시켜야 합니다.

## 1. 인증 및 인가 (Authentication & Authorization)
- **Q1. 관제사(User) 로그인 방식:** 프론트엔드 대시보드 접속 시 JWT 기반의 자체 로그인을 구현할 것인가, 아니면 OAuth(구글, 카카오 등)를 연동할 것인가?
- **Q2. AI 모듈(Equipment) API 인증:** 드론이나 CCTV가 이벤트 생성 엔드포인트를 호출할 때, 무단 접근을 막기 위해 어떤 인증 방식(예: API Key, JWT 토큰, IP 화이트리스트)을 적용할 것인가?

## 2. 실시간 통신 및 알림 (Real-time Communication)
- **Q3. 대시보드 실시간 업데이트:** 새로운 장애물(Event)이 DB에 인서트 되었을 때, 프론트엔드 대시보드가 이를 즉시 알 수 있도록 WebSockets이나 SSE(Server-Sent Events)를 구현해야 하는가? (현재는 단순 폴링/GET 요청으로 가정 중)

## 3. 데이터 보존 정책 (Data Retention)
- **Q4. 이미지 및 데이터 만료:** 서버 볼륨에 저장되는 장애물 이미지와 DB 레코드는 영구 보존할 것인가, 아니면 일정 기간(예: 30일)이 지나면 자동 삭제(Batch/Cron Job) 처리할 것인가?

## 4. AI-Backend-Frontend 데이터 연계
- **Q5. 백엔드 이미지 입력 방식:** AI 서버 분리 대신 백엔드 내부에서 YOLO 추론을 수행하는 방향이므로, 이벤트 생성/추론 API가 이미지를 `multipart/form-data`로 직접 받을지, 기존 저장 이미지 경로를 입력으로 받을지 확정해야 한다. 허용 파일 형식은 우선 `png`, `jpeg/jpg`로 정한다.
- **Q10. 실시간 영상 연계 방식:** 관제 화면의 실시간 영상은 백엔드가 `video_url`/`stream_url`을 관리해야 하는가, 아니면 프론트엔드가 별도 영상 소스를 직접 연결할 것인가?
- **Q11. 처리 기록 조회 범위:** 상태 변경 body의 `comment`는 선택값으로 받기로 했으나, 별도 코멘트 목록 조회 API까지 이번 범위에 포함할지 결정해야 한다.
- **Q13. 정보 부족 이벤트 처리 방식:** AI 탐지 결과에 필수 정보가 부족한 경우 이벤트 등록을 거부할 것인가, 별도 상태로 저장해 관제사가 인지하게 할 것인가?
- **Q14. AI 모델 실행 환경:** `ai_model` 내부 추론 코드는 확보했으나, EC2/로컬 실행을 위한 Python, `ultralytics`, `torch` 버전 및 CPU 추론 속도는 아직 확인이 필요하다.
- **Q16. 기존 `/api/v1` 호환 유지 여부:** 공식 프론트 연동 경로는 `/api`로 정했으나, 기존 `/api/v1/events` 계열을 개발 기간 동안 호환 유지할지 제거할지 결정해야 한다.
- **Q17. description 생성 규칙:** 프론트 `RoadkillEvent.description`은 백엔드 응답 DTO에서 생성할 수 있으나, 문장 생성 규칙과 포함 정보 범위를 확정해야 한다.
