# Step 4. 도메인 제약 조건 도출

## 1. 제약 조건 정의 기준

도메인 제약 조건은 데이터가 비즈니스 의미를 잃지 않도록 하는 논리적 가드레일이다.

이 단계에서는 DB 제약 조건이나 구현 코드를 작성하지 않고, 도메인 수준에서 지켜야 할 규칙만 정의한다.

## 2. User 제약 조건

| ID | 제약 조건 | 이유 |
| --- | --- | --- |
| C-USER-01 | User는 고유 식별자를 가져야 한다. | 이벤트 담당자와 코멘트 작성자를 구분해야 한다. |
| C-USER-02 | username은 비어 있을 수 없다. | 관제사를 식별하거나 표시해야 한다. |
| C-USER-03 | role은 허용된 역할 범위 안에 있어야 한다. | 관제사와 관리자 등 역할 혼선을 줄인다. |

## 3. Equipment 제약 조건

| ID | 제약 조건 | 이유 |
| --- | --- | --- |
| C-EQ-01 | Equipment는 고유 식별자를 가져야 한다. | 어떤 장비가 이벤트를 발생시켰는지 추적해야 한다. |
| C-EQ-02 | equipment_type은 허용된 장비 종류 안에 있어야 한다. | CCTV, 드론 등 장비 종류를 일관되게 관리해야 한다. |
| C-EQ-03 | location_name은 비어 있을 수 없다. | 장비 설치 또는 운용 위치를 사람이 이해할 수 있어야 한다. |
| C-EQ-04 | status는 허용된 장비 상태 안에 있어야 한다. | 장비 운영 상태를 일관되게 표현해야 한다. |

## 4. Event 제약 조건

| ID | 제약 조건 | 이유 |
| --- | --- | --- |
| C-EVT-01 | Event는 고유 식별자를 가져야 한다. | 관제사가 개별 이벤트를 구분해야 한다. |
| C-EVT-02 | Event는 반드시 하나의 Equipment와 연결되어야 한다. | 이벤트의 탐지 장비를 추적해야 한다. |
| C-EVT-03 | Event는 최초 등록 시 User와 연결되지 않을 수 있다. | AI가 먼저 이벤트를 등록하고 관제사는 이후 확인할 수 있다. |
| C-EVT-04 | obstacle_type은 비어 있을 수 없다. | 관제사가 장애물 종류를 확인해야 한다. |
| C-EVT-05 | confidence는 0.0 이상 1.0 이하 범위여야 한다. | AI 신뢰도 의미를 유지하기 위해 필요하다. |
| C-EVT-06 | latitude는 유효한 위도 범위 안에 있어야 한다. | 지도 표시와 위치 판단 오류를 막는다. |
| C-EVT-07 | longitude는 유효한 경도 범위 안에 있어야 한다. | 지도 표시와 위치 판단 오류를 막는다. |
| C-EVT-08 | status는 허용된 이벤트 상태 안에 있어야 한다. | 관제 처리 흐름을 일관되게 유지한다. |
| C-EVT-09 | image_url은 관제사가 탐지 근거를 확인할 수 있는 참조여야 한다. | 실제 장애물 여부 판단에 필요하다. |
| C-EVT-10 | bbox_x, bbox_y, bbox_width, bbox_height는 프론트엔드가 강조 박스를 그릴 수 있는 유효한 값이어야 한다. | 장애물 강조 표시가 틀어지는 것을 막는다. |
| C-EVT-11 | priority는 허용된 우선순위 체계 안에 있어야 한다. | 관제사가 우선 확인 대상을 일관되게 판단해야 한다. |
| C-EVT-12 | detected_at은 이벤트 발생 또는 등록 시점을 표현해야 한다. | 최신순 조회와 관제 판단에 필요하다. |

## 5. Comment 제약 조건

| ID | 제약 조건 | 이유 |
| --- | --- | --- |
| C-CMT-01 | Comment는 고유 식별자를 가져야 한다. | 개별 기록을 구분해야 한다. |
| C-CMT-02 | Comment는 반드시 하나의 Event에 연결되어야 한다. | 기록은 특정 이벤트에 대한 것이어야 한다. |
| C-CMT-03 | Comment는 반드시 하나의 User에 연결되어야 한다. | 누가 작성했는지 추적해야 한다. |
| C-CMT-04 | content는 비어 있을 수 없다. | 빈 처리 기록은 의미가 없다. |
| C-CMT-05 | content는 과도하게 길지 않아야 한다. | 관제 메모로 관리 가능한 수준이어야 한다. |
| C-CMT-06 | created_at은 코멘트 작성 시점을 표현해야 한다. | 처리 기록의 시간 순서를 확인해야 한다. |

## 6. 미결정 제약 조건

다음 제약은 도메인 모델에는 필요하지만 세부 기준은 아직 확정하지 않는다.

| 항목 | 미결정 내용 | 협의 대상 |
| --- | --- | --- |
| bbox 좌표 기준 | 픽셀 기준인지 정규화 좌표 기준인지 미정 | AI/프론트엔드 |
| bbox 기준점 | 좌상단 기준인지 중심점 기준인지 미정 | AI/프론트엔드 |
| priority 체계 | 숫자형 등급인지 문자열 등급인지 미정 | 전체 팀 |
| image_url 의미 | 이미지 파일 경로인지 영상 참조인지 미정 | AI/프론트엔드 |
| 정보 부족 이벤트 | 등록 거부인지 별도 상태 저장인지 미정 | PO/팀 협의 |

## 7. Step 4 결론

도메인 제약의 핵심은 `Event`의 관제 판단 데이터가 유효한 의미를 유지하도록 하는 것이다.

특히 위치, 신뢰도, bbox, priority, status는 관제 화면과 처리 흐름에 직접 영향을 주므로 후속 데이터베이스 설계와 구현 단계에서 반드시 검증 기준으로 반영해야 한다.
