# Step 1. 도메인 개념 핵심어 추출

## 1. 추출 기준

이 단계에서는 `context_packet.md`, 최종 요구사항 명세서, 최종 MVP 범위 정의서, ERD 추출 문서를 바탕으로 명사 중심의 도메인 후보를 추출한다.

이 단계는 개념 도출 단계이며, 물리 DB 설계나 API 설계는 다루지 않는다.

## 2. 핵심 업무 문장에서 추출한 명사

| 업무 문장 | 도메인 핵심어 |
| --- | --- |
| AI가 도로 위 동물 사체를 탐지한다. | AI 모듈, 도로, 동물 사체, 탐지 |
| AI 모듈이 탐지 결과를 백엔드에 전달한다. | AI 모듈, 탐지 결과, 백엔드 |
| 백엔드는 탐지 결과를 신규 장애물 이벤트로 등록한다. | 탐지 결과, 장애물 이벤트 |
| 관제사는 이벤트 목록과 상세를 확인한다. | 관제사, 이벤트 목록, 이벤트 상세 |
| 관제사는 위치, 신뢰도, 탐지 근거, bbox, priority를 확인한다. | 위치, 신뢰도, 탐지 근거, bbox, 우선순위 |
| 관제사는 이벤트 상태를 변경한다. | 관제사, 이벤트 상태 |
| 관제사는 필요한 경우 처리 기록을 남긴다. | 관제사, 처리 기록 |
| 시스템은 장비와 이벤트의 관계를 관리한다. | 장비, 이벤트 |

## 3. 엔티티 후보 목록

| 후보 | 의미 | 판정 |
| --- | --- | --- |
| User | 도로 관제사를 표현하는 사용자 개념 | 핵심 엔티티 |
| Equipment | CCTV, 드론 등 탐지 장비 개념 | 핵심 엔티티 |
| Event | AI가 탐지한 장애물 발생 기록 | 핵심 엔티티 |
| Comment | 이벤트에 대한 관제사의 처리 기록 또는 메모 | 핵심 엔티티, MVP 조건부 |
| AI Module | 탐지 결과를 생성하는 외부 시스템 | 외부 Actor, 엔티티 제외 |
| Frontend Dashboard | 관제사가 사용하는 화면 | 외부/표현 계층, 엔티티 제외 |
| Obstacle | 도로 위 장애물 자체 | Event의 속성으로 표현 |
| Location | 장애물 발생 위치 | Event의 속성으로 표현 |
| Bounding Box | 장애물 강조 박스 정보 | Event의 속성으로 표현 |
| Priority | 이벤트 처리 우선순위 | Event의 속성으로 표현 |
| Status | 이벤트 처리 상태 | Event의 속성으로 표현 |
| Detection | 다중 객체 탐지 단위 | MVP 제외 |
| EventStatusHistory | 상태 변경 이력 | MVP 제외 |

## 4. 핵심 엔티티 확정

| 엔티티 | 정의 | MVP 관점 |
| --- | --- | --- |
| User | 도로 관제사 또는 시스템 사용자를 나타낸다. | 조건부 포함. 처리자 식별과 코멘트 작성자 추적에 필요하다. |
| Equipment | 도로 장애물을 탐지하는 CCTV 또는 드론 장비를 나타낸다. | 조건부 포함. 이벤트의 발생 장비 식별에 필요하다. |
| Event | AI가 탐지한 도로 장애물 이벤트를 나타낸다. | Must-have. MVP의 중심 엔티티다. |
| Comment | 관제사가 이벤트에 남기는 처리 기록 또는 확인 메모를 나타낸다. | 조건부 포함. 처리 기록 기능을 포함할 때 사용한다. |

## 5. 엔티티로 만들지 않는 개념

| 개념 | 제외 이유 |
| --- | --- |
| AI Module | 시스템 외부에서 탐지 결과를 보내는 Actor이며, 내부 도메인 데이터가 아니다. |
| Frontend Dashboard | 화면/표현 계층이며 데이터 엔티티가 아니다. |
| Obstacle | 현재 MVP에서는 장애물 자체를 별도 생명주기로 관리하지 않고 Event의 장애물 종류로 표현한다. |
| Location | 독립 엔티티가 아니라 Event의 위치 속성이다. |
| Bounding Box | 독립 엔티티가 아니라 Event의 강조 표시 속성이다. |
| Detection | 다중 객체 탐지 확장을 위한 도메인이며 MVP 제외 범위다. |
| EventStatusHistory | 상태 변경 이력 고도화 도메인이며 MVP 제외 범위다. |

## 6. Step 1 결론

도메인 모델링의 핵심 엔티티는 `User`, `Equipment`, `Event`, `Comment` 네 가지다.

MVP의 중심은 `Event`이며, `User`, `Equipment`, `Comment`는 관제사 식별, 장비 식별, 처리 기록 요구사항을 지원하는 보조 도메인이다.

`Detection`, `EventStatusHistory`, `Equipment` 자체 위치 도메인은 MVP 제외 범위에 따라 모델링하지 않는다.
