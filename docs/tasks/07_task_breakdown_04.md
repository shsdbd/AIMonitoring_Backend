# Step 4. 의존성 및 순서 배치

## 1. 순서 배치 기준

티켓 순서는 기존 코드가 깨져 있는 지점인 Event 생성 흐름을 복구하는 데 최적화한다.

DB/모델 정합성이 먼저 맞아야 API와 서비스 구현이 가능하므로, 데이터 계층을 먼저 정리하고 라우터/서비스를 뒤에 배치한다.

## 3. 병렬 가능 작업

## 4. 주요 Blocker

| Blocker | 영향 | 해결 |
| --- | --- | --- |
| 기존 DB 볼륨에 구버전 `events` 테이블 존재 | 새 모델 적용 시 컬럼 충돌 가능 | 개발 환경 볼륨 초기화 또는 마이그레이션 결정 |
| 기본 Equipment 데이터 없음 | Event 생성 시 FK 오류 | seed 또는 임시 기준 데이터 생성 방식 결정 |
| AI 요청 형식 미정 | EventCreate 입력 방식 변경 가능 | MVP는 현재 이미지 업로드 기반으로 진행하고 후속 협의 여지 유지 |
| bbox 좌표 기준 미정 | 상세 검증 제약 강화 불가 | DB에서는 최소 제약만 적용 |

## 5. Step 4 결론

우선 구현 순서는 `DB 정합성 -> 공통 인프라 -> Event 스키마/service/router -> 검증`이다.

Comment와 인증/AI 검증은 Must-have 흐름 안정화 이후 조건부로 진행한다.
