# Step 3. MoSCoW 기반 필터링

## 1. 분류 기준

| 분류 | 기준 |
| --- | --- |
| Must-have | 없으면 MVP 핵심 가치 사슬이 작동하지 않는 기능 |
| Should-have | 중요하지만 임시 우회가 가능하거나 MVP 이후로 미룰 수 있는 기능 |
| Could-have | 완성도를 높이지만 핵심 시연에는 필수적이지 않은 기능 |
| Won't-have | 이번 MVP에서 명시적으로 제외할 기능 |

## 2. Must-have

| 항목 | 이유 |
| --- | --- |
| AI 탐지 결과 수신 | MVP 흐름의 시작점이다. |
| 신규 이벤트 등록 | 관제사가 확인할 대상이 필요하다. |
| 이벤트 목록 제공 | 관제사가 신규/미처리 이벤트를 인지해야 한다. |
| 이벤트 상세 제공 | 관제사가 실제 장애물 여부를 판단해야 한다. |
| 위치 정보 제공 | 지도 또는 위치 기반 확인이 필요하다. |
| 탐지 근거 이미지 또는 영상 참조 제공 | 관제사가 시각 근거를 확인해야 한다. |
| bbox 강조 정보 제공 | 프론트가 장애물 강조 박스를 그려야 한다. |
| priority 제공 | 관제사가 우선 확인 대상을 판단할 수 있어야 한다. |
| 이벤트 상태 변경 | 관제사가 처리 흐름을 관리해야 한다. |
| 오탐 구분 | AI 탐지 시스템에서 오탐 처리는 필수 업무 흐름이다. |
| 변경 상태 저장 및 재조회 | 관제 화면에서 최신 처리 상태가 보여야 한다. |
| 필수 정보 검증 | 관제 판단이 불가능한 이벤트가 정상 처리되면 안 된다. |

## 3. Should-have

| 항목 | 이유 |
| --- | --- |
| 처리 기록/코멘트 작성 | 조치 이력 관리에 중요하지만 상태 변경으로 최소 흐름은 시연 가능하다. |
| 처리 기록/코멘트 조회 | 코멘트 작성 기능과 함께 후순위 구현 가능하다. |
| 관제사 식별 정보 관리 | 실제 서비스에는 필요하지만 MVP에서는 단일 관제사 가정으로 축소 가능하다. |
| 장비 식별 정보 관리 | 장비 도메인은 필요하지만 MVP에서는 장비 ID만으로 우회 가능하다. |
| 관제사 권한 통제 | 보안상 중요하지만 MVP 시연에서는 단순 접근으로 시작 가능하다. |
| AI 요청 신뢰성 확인 | 실제 서비스에는 필요하지만 AI 파트 연계 형식 확정 후 적용하는 편이 안전하다. |

## 4. Could-have

| 항목 | 이유 |
| --- | --- |
| 관리자 역할 기반 사용자 관리 | 운영 편의 기능이며 핵심 관제 흐름과 직접 관련이 낮다. |
| 관리자 역할 기반 장비 관리 | 장비 등록/수정은 운영 관리 기능이다. |
| 오류 추적/운영 로그 고도화 | 개발에는 유용하지만 MVP 기능 시연의 중심은 아니다. |
| 장애물 종류 확장 | 현재 MVP는 동물 사체 중심이다. |
| 장비 종류 확장 | 현재는 CCTV/드론 계열 가정만으로 충분하다. |

## 5. Won't-have

| 항목 | 제외 이유 |
| --- | --- |
| AI 모델 학습 및 추론 로직 구현 | AI 파트 책임이며 백엔드 MVP 범위가 아니다. |
| 프론트엔드 화면 디자인 세부 구현 | 프론트엔드 파트 책임이다. |
| 대규모 분산 처리 인프라 | 졸업 작품 MVP에는 과도하다. |
| 완전한 고가용성 구성 | 단일 백엔드/DB 흐름 검증이 우선이다. |
| 다중 객체 탐지를 위한 별도 Detection 도메인 | 현재 범위는 이벤트당 단일 장애물이다. |
| 별도 EventStatusHistory 이력 테이블 | MVP에서는 최신 상태와 선택적 코멘트로 충분하다. |
| Equipment 자체 지도 좌표 관리 | MVP 지도 표시는 Event 위치 정보로 처리한다. |
| 고도화된 통계/분석 대시보드 | 관제 흐름 이후의 분석 기능이다. |

## 6. Step 3 결론

MVP는 Must-have만으로도 시연 가능한 관제 흐름을 구성해야 한다.

Should-have는 시간이 허용되면 포함하되, 일정이 부족하면 상태 변경 중심의 최소 관제 흐름을 우선한다.

Won't-have 항목은 이후 구현 프롬프트와 작업 티켓에서 다시 등장시키지 않는다.
