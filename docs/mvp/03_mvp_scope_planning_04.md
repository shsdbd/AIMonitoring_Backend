# Step 4. 제외 범위(Out of Scope) 선언

## 1. 선언 목적

이 문서는 이번 MVP에서 개발하지 않을 기능을 명시적으로 격리한다.

여기서 제외된 항목은 이후 `domain-modeling`, `database-design`, `task-breakdown`, `backend-implementation` 단계에서 구현 대상으로 다시 끌고 오지 않는다.

## 2. MVP 제외 범위

| ID | 제외 항목 | 제외 사유 |
| --- | --- | --- |
| OOS-01 | AI 모델 학습 및 추론 로직 | AI 파트 책임이며 백엔드 MVP 범위가 아니다. |
| OOS-02 | 프론트엔드 화면 디자인 세부 구현 | 프론트엔드 파트 책임이며 백엔드 범위가 아니다. |
| OOS-03 | 고도화된 통계/분석 대시보드 | 관제 흐름 이후의 분석 기능으로 MVP 핵심 가치 사슬에 포함되지 않는다. |
| OOS-04 | 대규모 분산 처리 인프라 | 졸업 작품 MVP에는 과도하다. |
| OOS-05 | 완전한 고가용성 구성 | 단일 백엔드/DB 기반 시연을 우선한다. |
| OOS-06 | 다중 객체 탐지용 별도 Detection 도메인 | 현재 범위는 이벤트당 단일 장애물 탐지다. |
| OOS-07 | 별도 EventStatusHistory 이력 테이블 | MVP에서는 이벤트 최신 상태와 선택적 코멘트로 처리 흐름을 표현한다. |
| OOS-08 | Equipment 자체 지도 좌표 관리 | MVP 지도 표시는 Event의 장애물 위치 좌표로 충분하다. |
| OOS-09 | 복잡한 역할/권한 관리 | MVP에서는 관제 흐름 검증이 우선이며, 인증/권한은 Should-have로 단계화한다. |
| OOS-10 | 관리자용 사용자/장비 관리 고도화 | 운영 관리 기능으로 MVP Critical Path에 직접 포함되지 않는다. |

## 3. 제외 범위가 아닌 항목

다음 항목은 세부 방식이 미정이더라도 MVP 핵심 흐름에 필요하므로 제외하지 않는다.

| 항목 | 이유 |
| --- | --- |
| bbox 정보 전달 | 프론트 장애물 강조 박스 표시의 핵심 데이터다. |
| priority 정보 | 관제사가 이벤트 확인 우선순위를 판단하는 데 필요하다. |
| 상태 변경 | 관제사의 처리 흐름을 보여주는 핵심 기능이다. |
| 오탐 구분 | AI 탐지 기반 시스템의 필수 예외 흐름이다. |
| 탐지 근거 이미지 또는 영상 참조 | 관제사가 실제 장애물 여부를 판단하는 근거다. |

## 4. 후속 단계 주의사항

| 후속 단계 | 주의사항 |
| --- | --- |
| domain-modeling | Won't-have로 선언된 Detection, EventStatusHistory, Equipment 좌표는 모델링하지 않는다. |
| database-design | 제외된 기능을 위한 테이블/컬럼을 추가하지 않는다. |
| task-breakdown | 제외된 기능을 개발 티켓으로 만들지 않는다. |
| implementation-prompt-writer | 제외 기능을 코딩 지시서에 포함하지 않는다. |
| backend-implementation | 제외 기능을 선제적으로 구현하지 않는다. |

## 5. Step 4 결론

이번 MVP는 관제사의 최소 업무 흐름을 증명하는 데 집중한다.

따라서 **AI 모델 구현, 프론트 디자인, 통계, 대규모 인프라, 다중 객체 탐지, 별도 상태 이력, 장비 좌표 관리, 복잡한 권한 관리**는 명시적으로 제외한다.
