# Step 2. 요구사항 출처 정리

## 1. 요구사항 출처 개요

이번 단계의 요구사항은 단순히 기능 목록을 만드는 것이 아니라, 앞서 승인된 서비스 목표와 실제 관제 업무 흐름에서 어떤 요구사항이 나오는지 추적할 수 있도록 정리한다.

| 출처 유형 | 출처 | 요구사항 도출 방향 |
| --- | --- | --- |
| 서비스 목표 | AI 기반 실시간 도로 장애물 관제 시스템 | AI 탐지 결과를 관제사가 빠르게 확인할 수 있어야 함 |
| 핵심 문제 | 사람이 직접 순찰하거나 CCTV를 감시해야 해서 발견이 늦음 | 수동 발견 의존도를 줄이고 신규 장애물 인지 시간을 줄여야 함 |
| 핵심 사용자 | 도로 관제사 | 관제사가 이벤트를 확인하고 상태를 관리할 수 있어야 함 |
| 백엔드 가치 | 안정적인 데이터 전달, 빠른 데이터 처리 | AI 탐지 결과가 누락 없이 프론트 화면까지 전달되어야 함 |
| ERD/도메인 근거 | User, Equipment, Event, Comment | 관제사, 장비, 탐지 이벤트, 처리 기록의 개념이 요구사항에 반영되어야 함 |
| 협업 미결정 사항 | AI/프론트 데이터 연계 | bbox, 알림 방식, 영상 연계는 협의 가능한 요구사항으로 분리해야 함 |

## 2. 이해관계자별 요구사항 출처

| 이해관계자 | 관심사 | 요구사항으로 이어지는 내용 |
| --- | --- | --- |
| 도로 관제사 | 장애물을 빠르게 인지하고 확인해야 함 | 신규 이벤트 알림, 이벤트 목록 확인, 위치 확인, 탐지 근거 화면 확인 |
| 도로 관리 조직 | 장애물 처리 현황을 추적해야 함 | 이벤트 상태 관리, 처리 기록, 완료/오탐 구분 |
| AI 파트 | 탐지 결과를 백엔드로 전달해야 함 | 장애물 종류, 신뢰도, 위치, bbox, 이미지/영상 근거 데이터 전달 |
| 프론트엔드 파트 | 관제 화면에 이벤트를 표시해야 함 | 이벤트 조회, 알림 표시, 지도 표시, 강조 박스 렌더링, 상태 변경 요청 |
| 백엔드 파트 | AI와 프론트 사이에서 데이터를 안정적으로 중계해야 함 | 탐지 이벤트 수신, 저장, 조회, 상태 변경, 정합성 검증 |

## 3. 목표별 요구사항 출처 매핑

| 상위 목표 | 요구사항 출처 | 도출될 요구사항 |
| --- | --- | --- |
| 도로 장애물 발견 지연 감소 | 핵심 문제, 관제사 업무 | AI 탐지 이벤트가 발생하면 관제사가 신규 이벤트를 인지할 수 있어야 함 |
| 관제사의 상황 확인 지원 | 완성 장면, 프론트 화면 | 관제사는 지도 위치와 탐지 근거 화면을 확인할 수 있어야 함 |
| 장애물 판단 정확도 보조 | AI 탐지 결과, bbox 정보 | 관제사는 AI가 표시한 장애물 강조 영역과 신뢰도를 확인할 수 있어야 함 |
| 처리 흐름 관리 | 관제 업무, 도로 관리 조직 | 관제사는 이벤트 상태를 확인 중, 처리 완료, 오탐 등으로 변경할 수 있어야 함 |
| 데이터 전달 안정성 확보 | 백엔드 핵심 가치 | 백엔드는 AI 탐지 결과를 저장하고 프론트가 조회 가능한 형태로 제공해야 함 |

## 4. 요구사항화할 때 주의할 점

| 항목 | 처리 방침 |
| --- | --- |
| AI 모델 구현 | 백엔드 요구사항에 포함하지 않음 |
| 프론트 UI 세부 디자인 | 요구사항에서는 화면이 제공해야 할 정보와 행동만 정의 |
| API 상세 스펙 | 아직 확정하지 않음 |
| DB 컬럼 상세 설계 | 아직 확정하지 않음 |
| bbox 좌표 기준 | 미결정 사항으로 유지 |
| 실시간 알림 방식 | 구현 방식이 아니라 “신규 이벤트 인지 가능” 요구로 표현 |
| 영상 연계 방식 | 백엔드/프론트 역할 분담은 추후 협의 |

## 5. Step 2 결론

이 프로젝트의 요구사항은 다음 5개 출처에서 도출된다.

1. **관제사의 업무 흐름**
2. **도로 장애물 발견 지연이라는 문제**
3. **AI 탐지 결과**
4. **프론트 관제 화면에서 필요한 표시 정보**
5. **백엔드의 안정적인 데이터 중계 역할**

따라서 이후 Step에서는 기능을 나열하기보다, **AI 탐지 이벤트가 관제사의 확인·판단·처리 흐름으로 이어지는 과정**을 중심으로 요구사항을 분해한다.
