# Step 8. 수용 기준 작성

## 1. 수용 기준 작성 기준

수용 기준은 각 요구사항이 실제로 충족되었는지 검증하기 위한 조건이다.

이 단계에서는 구현 방식이나 API 상세를 확정하지 않고, **사용자와 시스템 관점에서 어떤 결과가 나오면 요구사항을 만족했다고 볼 수 있는지**를 Given-When-Then 형식으로 정리한다.

## 2. AI 탐지 이벤트 등록 수용 기준

### AC-01. AI 탐지 결과가 정상 이벤트로 등록된다

| 구분 | 내용 |
| --- | --- |
| Given | AI 모듈이 동물 사체 탐지 결과를 생성했고, 관제 판단에 필요한 필수 정보가 준비되어 있다. |
| When | AI 모듈이 탐지 결과를 백엔드 시스템에 전달한다. |
| Then | 시스템은 탐지 결과를 신규 장애물 이벤트로 등록한다. |
| And | 등록된 이벤트는 관제사가 조회 가능한 상태가 된다. |

### AC-02. 필수 정보가 부족한 탐지 결과는 정상 이벤트와 구분된다

| 구분 | 내용 |
| --- | --- |
| Given | AI 모듈이 탐지 결과를 생성했지만 위치, 장애물 종류, 신뢰도, 탐지 근거 등 필수 정보 중 일부가 부족하다. |
| When | 해당 탐지 결과가 백엔드 시스템에 전달된다. |
| Then | 시스템은 해당 데이터를 정상 관제 이벤트와 구분한다. |
| And | 관제사가 잘못된 정보를 정상 처리 대상으로 오인하지 않도록 해야 한다. |

## 3. 관제사 신규 이벤트 인지 수용 기준

### AC-03. 관제사는 신규 이벤트를 인지할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 시스템에 새로운 장애물 이벤트가 등록되어 있다. |
| When | 관제사가 관제 화면을 확인한다. |
| Then | 관제사는 신규 이벤트가 발생했음을 인지할 수 있다. |
| And | 실시간 알림 방식이 확정되지 않았더라도 목록 갱신 등을 통해 신규 이벤트를 확인할 수 있어야 한다. |

### AC-04. 관제사는 미처리 이벤트를 구분할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 시스템에 여러 장애물 이벤트가 등록되어 있고 일부는 아직 처리되지 않았다. |
| When | 관제사가 이벤트 목록을 확인한다. |
| Then | 관제사는 미처리 이벤트와 처리 완료 또는 오탐 이벤트를 구분할 수 있다. |

## 4. 이벤트 목록/상세 확인 수용 기준

### AC-05. 관제사는 이벤트 목록을 확인할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 하나 이상의 장애물 이벤트가 시스템에 등록되어 있다. |
| When | 관제사가 이벤트 목록을 확인한다. |
| Then | 시스템은 관제사가 업무 판단에 필요한 이벤트 요약 정보를 제공한다. |
| And | 요약 정보에는 장애물 종류, 발생 시각, 처리 상태, 우선순위 등 관제 판단에 필요한 항목이 포함되어야 한다. |

### AC-06. 관제사는 이벤트 상세 정보를 확인할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 관제사가 특정 이벤트를 선택했다. |
| When | 관제사가 이벤트 상세 정보를 확인한다. |
| Then | 시스템은 해당 이벤트의 위치, 장애물 종류, 신뢰도, 발생 시각, 상태, 우선순위, 탐지 근거 정보를 제공한다. |

### AC-07. 관제사는 장애물 위치를 지도 또는 위치 정보로 확인할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 이벤트에 위치 정보가 포함되어 있다. |
| When | 관제사가 이벤트 상세 정보를 확인한다. |
| Then | 관제사는 장애물이 발생한 위치를 파악할 수 있다. |

## 5. 장애물 강조 표시 수용 기준

### AC-08. 관제사는 장애물 강조 영역을 확인할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 이벤트에 장애물 강조 표시를 위한 bbox 정보가 포함되어 있다. |
| When | 관제사가 탐지 근거 화면을 확인한다. |
| Then | 관제사는 AI가 장애물로 판단한 영역을 강조 박스로 확인할 수 있다. |

### AC-09. 강조 표시 정보가 부족한 경우 관제사가 이를 인지할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 이벤트에는 탐지 근거 정보가 있지만 bbox 정보가 없거나 표시할 수 없는 상태다. |
| When | 관제사가 이벤트 상세 정보를 확인한다. |
| Then | 관제사는 장애물 강조 표시 정보가 부족하다는 사실을 인지할 수 있어야 한다. |

## 6. 이벤트 상태 변경 수용 기준

### AC-10. 관제사는 이벤트 상태를 확인 중으로 변경할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 관제사가 미확인 이벤트를 확인하고 있다. |
| When | 관제사가 해당 이벤트 상태를 확인 중으로 변경한다. |
| Then | 시스템은 변경된 상태를 저장한다. |
| And | 이후 목록과 상세 화면에서 변경된 상태가 확인된다. |

### AC-11. 관제사는 이벤트 상태를 처리 완료로 변경할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 관제사가 실제 장애물 처리 또는 상황 종료를 확인했다. |
| When | 관제사가 이벤트 상태를 처리 완료로 변경한다. |
| Then | 시스템은 해당 이벤트를 처리 완료 상태로 저장한다. |
| And | 해당 이벤트는 미처리 이벤트와 구분된다. |

### AC-12. 관제사는 이벤트 상태를 오탐으로 변경할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 관제사가 탐지 근거를 확인한 뒤 실제 장애물이 아니라고 판단했다. |
| When | 관제사가 이벤트 상태를 오탐으로 변경한다. |
| Then | 시스템은 해당 이벤트를 오탐 상태로 저장한다. |
| And | 해당 이벤트는 실제 처리 대상 이벤트와 구분된다. |

## 7. 처리 기록 수용 기준

### AC-13. 관제사는 처리 기록을 작성할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 관제사가 특정 이벤트를 확인했다. |
| When | 관제사가 확인 내용, 조치 내용, 오탐 사유 등 기록을 작성한다. |
| Then | 시스템은 해당 기록을 이벤트와 연결해 저장한다. |

### AC-14. 관제사는 이벤트별 처리 기록을 조회할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 특정 이벤트에 하나 이상의 처리 기록이 저장되어 있다. |
| When | 관제사가 해당 이벤트를 다시 확인한다. |
| Then | 시스템은 해당 이벤트에 연결된 처리 기록을 제공한다. |

## 8. 권한 및 보안 수용 기준

### AC-15. 허가된 관제사만 관제 기능을 사용할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 사용자가 관제 이벤트 조회, 상태 변경, 기록 작성 기능에 접근하려 한다. |
| When | 사용자의 권한이 확인된다. |
| Then | 허가된 관제사만 해당 기능을 사용할 수 있어야 한다. |

### AC-16. 신뢰 가능한 AI 모듈만 이벤트를 등록할 수 있다

| 구분 | 내용 |
| --- | --- |
| Given | 외부 시스템이 신규 이벤트 등록을 시도한다. |
| When | 시스템이 요청의 신뢰 여부를 판단한다. |
| Then | 허가된 AI 모듈 또는 장비만 정상 이벤트를 등록할 수 있어야 한다. |

> 인증 방식은 아직 미정이며, 이 수용 기준은 “접근 통제가 필요하다”는 수준의 요구사항이다.

## 9. 데이터 정합성 수용 기준

### AC-17. 이벤트 데이터는 유효 범위를 벗어나지 않아야 한다

| 구분 | 내용 |
| --- | --- |
| Given | 이벤트에 위치, 신뢰도, bbox, 우선순위 등의 값이 포함되어 있다. |
| When | 시스템이 이벤트를 등록하거나 갱신한다. |
| Then | 시스템은 관제 판단과 화면 표시에 부적절한 값이 저장되지 않도록 해야 한다. |

### AC-18. 상태값은 정의된 업무 상태 안에서만 변경된다

| 구분 | 내용 |
| --- | --- |
| Given | 관제사가 이벤트 상태 변경을 시도한다. |
| When | 변경하려는 상태값이 정의된 업무 상태에 포함되지 않는다. |
| Then | 시스템은 해당 상태 변경을 정상 처리하지 않아야 한다. |

## 10. Step 8 결론

수용 기준은 다음 흐름을 검증할 수 있어야 한다.

1. AI 탐지 결과가 정상 이벤트로 등록되는가?
2. 관제사가 신규 이벤트와 미처리 이벤트를 인지할 수 있는가?
3. 관제사가 위치, 신뢰도, 탐지 근거, bbox 강조 영역을 확인할 수 있는가?
4. 관제사가 상태 변경과 처리 기록을 남길 수 있는가?
5. 시스템이 권한, 필수 정보, 데이터 유효성을 적절히 통제하는가?
